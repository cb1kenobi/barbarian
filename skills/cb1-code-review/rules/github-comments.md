# GitHub review comments

Fetch existing inline and top-level comments first. Skip any finding already described at the same code path, whether it came from a human or an agent.

Post all new inline findings as one review against the exact head SHA. Anchor only to changed lines: `RIGHT` for added or changed lines, `LEFT` for removed lines. If the underlying bug is on an unchanged line, anchor to the nearest changed line in the same hunk and name the true location in the body.

Each comment is concise:

```text
**High: concise problem**

Concrete failure and when it occurs.

Suggested fix: the smallest specific correction.

—
_Generated by Barber AI_
```

Use a GitHub suggestion block only for a literal replacement. Use `COMMENT` for informational findings and `REQUEST_CHANGES` only when the user asked the reviewer to submit that formal verdict. A clean review updates Barbarian's local status only and must not post a top-level comment or submitted review to GitHub.
